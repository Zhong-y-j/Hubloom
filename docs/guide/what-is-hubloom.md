# Hubloom 是什么？

> **一句话概括：Hubloom 是 AI Agent 时代的「基座脚手架」——就像 Spring Boot 之于后端、Vue Admin 之于后台管理。**

它不是一个聊天机器人产品，而是一个**让你现有业务系统快速长出 AI 能力的开发起点**：接上 Swagger/OpenAPI，用户就能用自然语言在**真实 API** 上查询与办事。

---

## 它解决什么问题？

很多团队想引入 AI Agent，但一上手就遇到三个现实问题：

| 问题       | 具体表现                                                     |
| ---------- | ------------------------------------------------------------ |
| **接入难** | Agent 要调用现有 API，得自己写工具封装、参数拼装、错误处理   |
| **交互难** | Agent 只能「说话」，不能「办事」——用户要操作还得去另一个页面 |
| **易锁定** | 用某个云平台的 Agent 服务后，代码和配置容易绑在那            |

**Hubloom 的解法：**

> 不重新发明业务系统，而是用**开放协议 + 可二开模板**，把「对话 → 调 API → 出结果」这条链路标准化。

---

## Hubloom 到底能做什么？

下面按「开箱主能力」和「按需打开」分开看，避免把脚手架误读成「什么都要一次配齐」。

### 开箱主能力（主路径）

| 能力             | 你得到什么                                                                                                                 |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **契约即工具**   | 配上 OpenAPI/Swagger，接口进入工具面；Agent 用 `list_api` / `call_api` 调真实 REST，而不是假聊天                           |
| **双通道呈现**   | **Markdown**：结论、核对表、说明；**A2UI**：表单 / 列表 / 确认等可操作界面（`present_mode`：`markdown` / `a2ui` / `auto`） |
| **标准回合交互** | `/v1/chat` 走 AG-UI 风格 SSE：流式文本、工具过程、表单等待与结构化回传（可核对、可复盘）                                   |
| **多轮会话**     | 按 `session_id` 记历史；业务 Token 由请求传入，不写死在配置里                                                              |
| **Skill 规程**   | 在 `skills/` 写领域 Know-how（先查什么、怎么确认、禁区），约束 Agent「按你们业务办事」                                     |
| **两种交付**     | **示例站**开箱演示；**Runtime** 只嵌 `/v1/chat` 等进自有门户                                                               |

### 按需打开（不挡主路径）

| 能力               | 适用场景                                     | 文档                                                      |
| ------------------ | -------------------------------------------- | --------------------------------------------------------- |
| **事件 Webhook**   | 业务系统推事件 → Agent 主动跑一轮 → 写入会话 | [事件 Webhook](../advanced/webhook.md)                    |
| **企业微信入口**   | 手机企微单聊，同一 Runtime，Markdown 推回    | [企业微信入口](../advanced/wecom-integration.md)          |
| **A2A**            | 跨 Agent 委托（可选）                        | [A2A](../advanced/a2a.md)                                 |
| **长期记忆 / RAG** | 跨会话沉淀、文档问答（可选）                 | [记忆](../advanced/memory.md) · [RAG](../advanced/rag.md) |

> 会话历史默认就有；**长期记忆**、RAG、事件、企微等才是「开关类」能力。

### 几个具体画面（帮助建立直觉）

- 「查一下某某柜子状态」→ Agent 调 API → Markdown / 表格核对
- 「帮我创建小区再补钥匙柜」→ 多步工具调用 → 表单补参 → 确认后落库
- 业务系统 `POST /v1/events`（如柜子已登记）→ 无人先开口，Agent 按分册规程处理并写入历史
- 用户在企微发「你好」→ 换业务 Token → 同一套 Agent → 回复推回手机

界面长什么样，可先看文档首页的 [界面预览](../README.md#️-界面预览)，或跑通后自己打开示例站。

## Hubloom 到底包含什么？

| 组成部分                        | 说明                                             |
| ------------------------------- | ------------------------------------------------ |
| **示例站（`examples/chat`）**   | 对话页 + A2UI 面板，按快速上手即可体验完整主路径 |
| **Runtime（`HubloomRuntime`）** | 编排、工具、SSE、会话；可被示例站或自有应用调用  |
| **协议适配**                    | MCP / A2UI / AG-UI（见下节，先不用深挖）         |
| **Skill 扩展点**                | `skills/` 写规程；真正调 API 仍走企业 HTTP       |

**你不必全用。** 可以先用示例站；落地时也可以只嵌 Runtime。

## 和「聊天机器人」有什么区别？

| 维度     | 旁路聊天机器人        | Hubloom                                    |
| -------- | --------------------- | ------------------------------------------ |
| 定位     | 一个独立的产品 / 页面 | 嵌入现有系统的**开发基座**                 |
| 交互     | 一问一答，多为纯文本  | Markdown 说明 + A2UI **可操作界面**        |
| 业务集成 | 往往要额外开发对接    | **接上 Swagger**，对话即调真实 API         |
| 过程     | 黑盒回复居多          | 工具链 / SSE 事件可上屏、可复盘            |
| 部署     | 常见为 SaaS           | **可私有化**，代码在你手里                 |
| 扩展     | 平台给什么用什么      | **Skill + 配置**；可选事件 / 企微 / RAG 等 |

> Hubloom 不是让你「多一个聊天窗口」，而是让你**现有的业务系统能听懂人话，并在需要时给出可操作的界面**。

## 核心设计理念

### ① 协议驱动，而非代码锁定

- **MCP**：HTTP API → Agent 工具
- **A2UI**：声明式表单 / 表格 / 确认（示例站可直接用；自研前端需对接 AG-UI）
- **AG-UI**：前端与 Agent 的 SSE 交互事件

> 换模型、换 Swagger：**主要改配置**。换皮与领域规程：走二次开发面，**不必重写 Runtime 核心**。

### ② 嵌入优先，而非替代系统

业务逻辑仍在你的服务里。Hubloom 主要做：

- **翻译**：用户意图 → 调哪些 API、怎么呈现
- **路由**：工具结果 → Markdown 或 A2UI

### ③ 脚手架，而非平台

给你的是可二开仓库 + 可私有化服务 + 可选能力开关；  
不是锁死的 SaaS，也不是替你重做业务系统 / BPM。

## 你用 Hubloom，具体要做什么？

| 你负责                                     | Hubloom 底座负责                              |
| ------------------------------------------ | --------------------------------------------- |
| 配置 LLM 和 Swagger                        | 工具调用（MCP）                               |
| 编写 Skill（领域规程）                     | Think / Present / Respond 编排与 SSE（AG-UI） |
| 按需定制前端或嵌入门户                     | 会话历史                                      |
| 按需开启长期记忆 / RAG / A2A / 事件 / 企微 | 鉴权透传与过程可观测                          |

业务 API 与数据仍在你的服务里；Skill 约束「怎么办事」，不代替后端实现。

---

## 总结

> **Hubloom 是一个让你「把 AI Agent 接到现有业务系统上」的开发基座。**

主路径通常是：

1. 配好 LLM 和 Swagger → **对话能调真实 API**
2. 按需写 Skill → **按你们业务规矩办事**
3. Markdown 说明 + A2UI 办事 → **说得清、办得完**
4. 需要时再开事件 / 企微 / RAG 等 → **同一 Runtime，多入口**

**Hubloom 不替代你的系统，它让你的系统听懂人话。**
